# DSR-003：每实例独立的 codexpro 数据目录

> **决定**：`CODEXPRO_HOME` 指向 `<$DSH_HOME>/codexpro`，**不共用**默认 `~/.codexpro`。
> **理由**：与仓库「实例隔离只能按 HOME」的硬规则一致；避免多实例共用端口与 profile 引发的互踩。
> **被否决项**：沿用默认 `~/.codexpro`；默认隔离 + 设置页开关可切换。

## 上下文

codexpro 的数据目录由 `CODEXPRO_HOME` 决定，默认 `~/.codexpro`，内含 `profiles/`（配置）与 `runtime/`（运行态）。

本机存在三个 DSH 实例（`stable-dev`、`test`、`dev`），各有独立 `$DSH_HOME`。仓库既有硬规则：**环境按实例（HOME）区分，两个 DSH 实例共用同一 HOME 属禁止行为**，理由是会话日志写防护与启动扫描都按 HOME 生效。

codexpro 侧另有一层具体风险：默认端口 `8787` 固定，两个实例若共用同一数据目录且同时启动，第二个实例必然遇到端口冲突。

## 真实方向及评价

| 方向 | 实例隔离 | 与终端手工使用的关系 | 代价 |
|------|----------|----------------------|------|
| 每实例独立（`$DSH_HOME/codexpro`） | 完整 | 终端手跑 codexpro 看到的是 `~/.codexpro`，**两边不互通** | 在终端 `codexpro setup` 过的项目不会自动出现在勾选列表 |
| 沿用默认 `~/.codexpro` | 无 | 完全共享 | 多实例共用一份配置与端口；一个实例改了授权，另一个实例的行为随之变化 |
| 默认隔离 + 开关切换 | 可选 | 取决于开关 | 多一个需要解释的概念，以及一套「两边内容冲突时怎么办」的处置规则 |

## 最终决定与理由

取**每实例独立**。

理由：隔离是仓库既有的硬性安全取向，且此处的耦合后果具体而不抽象——共用数据目录意味着在 `test` 实例里做实验会改变 `stable-dev` 的授权范围，而授权范围正是「ChatGPT 能读写哪些本地目录」这一安全边界的定义。

第二个方向的「便利」（终端配置自动可见）在本插件的定位下价值有限：本插件的目的就是让用户**不必**在终端手工维护 codexpro 配置；授权候选集来自 DSH 工作区注册表，本来就不依赖终端侧的既有 profile。

第三个方向的开关被否决，因为它引入的状态空间大于收益：需要定义「切换时如何合并两边内容」，而该合并语义无法给出无歧义的解释。

## 直接后果

- 插件的授权集与终端手工使用的 codexpro 配置**互不影响**。
- 用户在终端 `codexpro start` 与在 DSH 设置页启动，是两个独立环境（不同端口需自行区分）。
- 卸载插件不清理 `$DSH_HOME/codexpro`（属用户数据，与 DSH 其他 HOME 级数据同待遇）。
- 该目录随 `$DSH_HOME` 迁移，不随实例版本升级而变。

## 重访条件

- 用户明确要求「终端与 DSH 共用同一套 codexpro 配置」，且接受跨实例耦合。
- codexpro 支持按项目而非按 HOME 完全隔离的配置寻址，使共用不再有耦合风险。
