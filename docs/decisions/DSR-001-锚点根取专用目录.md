# DSR-001：锚点根取专用目录

> **决定**：codexpro 的 `--root` 取 `<$DSH_HOME>/codexpro/anchor` 专用目录。
> **理由**：profile 文件名由 `sha256(realpath(root))` 决定，锚点必须与授权集无关才不漂移。
> **被否决项**：指定一个工作区作主项目；锚点 = 首个授权工作区。

## 上下文

codexpro 的配置按「工作区根目录」组织：`CODEXPRO_HOME/profiles/<sha256(realpath(root)).slice(0,24)>.json`。锚点根同时决定两件事：

1. profile 文件的身份（文件名）；
2. ChatGPT 侧 `open_current_workspace` 的落点，以及 `.ai-bridge` 计划文件、`AGENTS.md` 上下文读取的默认目录。

本插件需要「勾选授权的项目集合」是可变的，而 profile 文件身份必须稳定——否则每调整一次勾选就产生一个新 profile 文件，旧文件残留且配置看似丢失。

## 真实方向及评价

| 方向 | 稳定性 | ChatGPT 默认上下文 | 代价 |
|------|--------|--------------------|------|
| 专用锚点目录 | 完全稳定，与勾选集无关 | 锚点为空目录；实际用 `open_workspace` 选项目 | 默认上下文不是真实项目 |
| 指定一个工作区作主项目 | 稳定，除非用户换主项目或将其移出 DSH | 默认上下文即真实项目 | 该项目若被移出 DSH 工作区清单，锚点失效，需回退处置 |
| 锚点 = 首个授权工作区 | **不稳定**：勾选顺序变化即换 profile 文件 | 跟随首个授权项 | 配置漂移、旧 profile 残留 |

## 最终决定与理由

取**专用锚点目录**。

理由：稳定性是硬要求（profile 身份必须可预测），而 ChatGPT 默认上下文的损失有明确替代路径——codexpro 的 MCP 工具集包含 `open_workspace`，ChatGPT 会显式选择已授权项目；`open_current_workspace` 只是「回到主项目」的便利。以一处便利换取配置身份的确定性，是划算的。

同时避免了第二个方向的连带复杂度：若锚点是某个真实工作区，就必须处理「该工作区被移出 DSH 清单」这一状态，以及随之而来的锚点回退策略与用户告知。

## 直接后果

- 首次同步时由插件创建锚点目录（`mkdir` recursive）。
- 用户更换勾选集合**不改变** `profilePath`。
- ChatGPT 的 `open_current_workspace` 落在锚点目录（空目录）；使用中应以 `open_workspace` 切换项目。
- 配置项 `anchorDir` 保留覆盖能力（非 volatile，属部署事实），默认空即用推导值。

## 重访条件

- ChatGPT 侧工作流被证明强依赖 `open_current_workspace` 落在真实项目，且 `open_workspace` 不足以补偿。
- codexpro 改变 profile 身份推导方式（不再以 root 路径为输入），使漂移顾虑消失。
