# 技术栈设计

## 权威范围

本文是 `dsh-codexpro` 的技术栈定调文档，唯一拥有语言与运行时、框架与关键库、版本基线、部署目标、兼容与安全约束及选型理由。模块边界与目录组织归 `项目结构设计.md`，机制细节归 `technical-details/`，需求语义归 `需求.md`。实质变更属于重大决策，须写入决策记录并核对依赖文档。

## 一、运行时与语言基线

| 项 | 取值 | 依据 |
|----|------|------|
| Node.js | `^22.19.0 \|\| >=24` | 与 DSH 包基线一致；本机实测 `v24.12.0` |
| 包管理器 | pnpm | 仓库既有约定 |
| Host 半区语言 | JavaScript（ESM，`.js`），无构建步骤 | 与 `dsh-skill-manager` / `dsh-unity-search` 现行形态一致 |
| Client 半区语言 | JSX，经 esbuild 打包为惰性 CJS factory | DSH client bundle 契约 |

Host 半区不引入 TypeScript：本插件无对外类型面（不提供工具、不注册 Service），JS + JSDoc 足以承载约束，省去一套构建链。Client 半区必须构建，产物入库。

## 二、DSH 版本基线与 peer 声明

**基线**：`0.1.7-rc.2`（本机部署运行时与知识库 active 版一致，`dshl env --json` 现查）。

**peer 范围硬性规则**：`cordis` 与携带 Service Definition 的 `@deepseek-ai/dsh-*` 必须置于 `peerDependencies`；装载期 import 的同时列同版本 `devDependencies`。`@deepseek-ai/schemastery` 与 `cosmokit` 可置于 `dependencies`。

本插件的 peer 声明：

| 包 | 版本范围 | 位置 | 理由 |
|----|----------|------|------|
| `@deepseek-ai/cordis` | `^4.0.4` | peer + dev | 插件形态与 `Service`/`effect` 契约来源；装载期 import 类型 |
| `@deepseek-ai/dsh-workspace` | `^0.1.7-rc.2` | peer + dev | `ctx.workspaceRegistry` 的类型与运行时定义在此包 |
| `@deepseek-ai/dsh-subprocess` | `^0.1.7-rc.2` | peer | `ctx.subprocess` 服务定义所在；仅类型消费，运行时由宿主提供 |
| `@deepseek-ai/dsh-settings` | `^0.1.7-rc.2` | peer | 设置表单面（`ctx.settings.configure`） |
| `@deepseek-ai/schemastery` | `^3.18.4` | dependencies | `Symbol.for` 跨边界身份，双副本无害；装载期 import 用于声明 `Config` |

**范围判定必须带 `includePrerelease`**：DSH 的兼容性检查调用 `semver.satisfies(runtimeVersion, range, { includePrerelease: true })`。用 npm 默认语义复核会得出相反结论（预发布运行时默认不匹配任何范围）。上表范围在 `0.1.7-rc.2` 下判定为满足。

## 三、关键库选型

| 库 | 用途 | 理由与重访条件 |
|----|------|----------------|
| `@deepseek-ai/schemastery` | 声明插件 `Config` schema | DSH 唯一受支持的配置声明面。若上游迁移配置声明机制，随之重访 |
| `@deepseek-ai/dsh-client-ui-primitives` | 设置页 UI 原语（`Button`/`Checkbox`/`Tag`/`StateDot`/图标） | 宿主设计体系的既有实现，直接复用避免自绘几何漂移。若原语移除所需组件（如 `Checkbox`），改为自绘同构壳并登记决策 |
| esbuild | Client bundle 构建 | 与仓库既有两个 Client 插件一致，可与它们共享构建脚本形态 |

不引入 HTTP 客户端库：健康检查使用 Node 内建 `fetch`（Node ≥22 具备）。

## 五、兼容与平台约束

**平台策略**：Windows 为首要目标平台，但平台相关行为必须经抽象隔离（C-08）。

| 平台相关面 | 隔离方式 | 当前证据等级 |
|------------|----------|--------------|
| 路径拼接与归一 | 统一经 `node:path`，不手写分隔符；realpath 归一用 `fs.realpathSync.native` | 已验证（Windows） |
| 进程终止 | 主路径向 stdin 写 `q`；兜底经 `ctx.subprocess` 句柄的 `terminate()` | **已验证（Windows）**：`q` 触发完整清理；容器整树终止可用 |
| 可执行文件定位 | 经包解析取 codexpro CLI 入口，以 `process.execPath` 执行 | **已验证（Windows）**；POSIX 未取证 |
| shell 调用 | 本插件不调用 shell；`codexpro` 以 `argv` 数组直接 spawn | 由 `ctx.subprocess` 契约保证（`argv` 绝不经 shell 解释） |

**不支持任何未经实测的平台声明**：README 与文档明确写明当前仅在 Windows + DSH `0.1.7-rc.2` 上验证通过。其他平台列为 `missing evidence`，待有实测证据再声称支持。

**codexpro 版本约束**：本设计锚定 `codexpro@0.30.2`。插件在启动前探测其对外的版本输出，与已知可用版本区间不符时以警告呈现，不静默继续。

## 六、安全约束

| ID | 约束 |
|----|------|
| S-01 | HTTP token 不得写入任何日志、UI 明文以外的持久位置、或错误消息；呈现 Server URL 是唯一例外（用户需要它填连接器） |
| S-02 | token 经 codexpro profile 文件传递，**不经 spawn 环境变量**。宿主 `ctx.subprocess` 的环境清洗规则会剔除名称匹配 `KEY\|PASSWORD\|SECRET\|TOKEN` 的变量，`CODEXPRO_HTTP_TOKEN` 命中该规则，经 env 传递会静默丢失 |
| S-03 | 授权集只接受 DSH 工作区注册表中的目录；写入前校验目录存在，不存在则不写入（codexpro 对不存在的授权根直接拒绝启动） |
| S-04 | 首次配置的 tunnel 默认值为 `none`，不产生公网入口；启用公网 tunnel 是显式选择 |
| S-05 | 健康检查与状态查询只访问回环地址；不向公网发起探测 |
| S-06 | 本插件不读取、不存储 ChatGPT 凭据；不接触 codexpro 的 tunnel 凭据文件 |

## 七、安全边界的诚实声明

codexpro 官方文档明确其定位是**本地开发桥，不是操作系统级沙箱**。本插件不改变这一点，也不得在 UI 或文档中暗示它提供了额外隔离：

- 授权一个目录即等于允许 ChatGPT 在该目录内读写与执行受控命令（受 `bash` 模式与 codexpro 内建路径黑名单约束，而非受 DSH 沙箱约束）。
- 插件 spawn 的子进程**不受 DSH 沙箱约束**（DSH 的沙箱作用于工具调用，不作用于插件代码）；`ctx.subprocess` 只提供环境清洗与进程生命周期管理。
- 公网 tunnel 意味着该 URL 持有 token 即可访问本地仓库，token 因此等价于凭据。

## 八、选型重访条件

| 选型 | 重访触发条件 |
|------|--------------|
| Host 半区不引入构建步骤 | 出现需要类型生成或非 JS 源码的场景 |
| `github:` 交付通道 | npm 发布完成，或 `github:` 的 `prepare` 授权成为阻碍 |
| 复用 `@deepseek-ai/dsh-client-ui-primitives` | 原语包 API 变更，或所需组件被移除 |
| 锚定 `codexpro@0.30.2` | codexpro 发布破坏性变更（启动参数、profile 文件形状、健康端点） |
| Windows 优先 | 获得其他平台的实测证据，或上游要求跨平台支持 |
