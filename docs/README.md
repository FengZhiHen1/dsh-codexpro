# dsh-codexpro 设计

## 主题目标

把 CodexPro 的配置与进程生命周期收进 DSH 设置页：以 DSH 工作区注册表为唯一授权来源，在插件设置页勾选要授权给 ChatGPT 的项目、控制 codexpro 进程启停、选择公网 tunnel 方式，日常使用不再需要手工维护 codexpro 配置。

## 已知偏差与缺证

- `missing evidence`：**codexpro 的优雅停止路径**。源码显示存在信号处理器与非 TTY 下的 stdin `q` 通道，但 Windows 上外部发送信号**不执行**其 JS 处理器（实测：目标进程注册处理器并在其中写标记文件；发信号后进程消失而标记文件未生成）。这会使 `cleanup()` 不运行，server 与 tunnel 可能成为孤儿。终止机制的主路径须实测后定型（`TODO.md` T-01，候选与降级顺序见 `technical-details/进程管理.md` §五）。
- `missing evidence`：**`ctx.subprocess` 的 Windows 进程容器是否在本机激活**。该 seam 承诺「服务销毁会终止所有仍在运行的托管进程并等待其退出」，但整树能力取决于 Windows 进程容器实际是否可用（`TODO.md` T-02）。
- `missing evidence`：**非 Windows 平台的行为**。全部取证在 Windows + DSH `0.1.7-rc.2` 上完成。C-08 要求实现按可移植标准编写（平台差异隔离在可执行解析一层），但**不支持任何未经实测的平台声明**。
- 待确认：codexpro 版本漂移。全部分析锚定 `0.30.2`；上游改变启动参数、profile 形状或健康端点会使本文档失效（`TODO.md` T-06）。
- 注意：本设计与实现均未开始，上述「已成文」指文档交付，不代表任何代码或实测结果。
