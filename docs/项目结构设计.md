# 项目结构设计

## 权威范围

本文是 `dsh-codexpro` 的项目结构定调文档，唯一拥有目标目录结构、模块边界、依赖方向与命名约定。技术选型归 `技术栈设计.md`；各机制内部语义归 `technical-details/`。实质变更属于重大决策，须写入决策记录并核对依赖文档。

## 二、分层与依赖方向

core / adapter 两层划分是本仓库新插件的硬性约定，由 `tools/plugin-layering-check.mjs` 机检。

```text
core/*  ←  adapter/*
```

- `src/core/` 禁止 import `@deepseek-ai/*`（含 cordis），禁止相对路径反引 adapter；只依赖 `node:*` 与 core 内部。
- `src/adapter/` 是全包唯一允许接触 DSH 运行时的层。
- `src/client/` 为浏览器半区，不得 import Host 侧模块；跨包只允许 type-only import。

**core 模块职责**

| 模块 | 职责（唯一承载） |
|------|------------------|
| `core/codexpro.js` | codexpro 事实常量单一收口：启动参数名与取值枚举、`Config` 字段默认值、已知可用版本区间、`CODEXPRO_*` 环境变量名。**不承载流程** |
| `core/anchor.js` | 锚点根与 dataHome 的纯推导：给定 `$DSH_HOME` 得到锚点目录与 `CODEXPRO_HOME`；路径拼接与归一 |
| `core/profile.js` | profile 身份与内容：`sha256(realpath(root)).slice(0,24)` 文件名推导、payload 形状构造、`allowedRoots` 排序与去重规则 |
| `core/catalog.js` | 授权变换：DSH 工作区列表 → 授权候选集（含存在性标记）；勾选集 → `allowedRoots` 列表（校验 + realpath 去重 + 排序）；拒绝不可用项 |
| `core/state.js` | 进程状态机纯转移：`idle → starting → running → stopping → idle`，含 `failed` 分支与允许的转移表 |
| `core/health.js` 归 adapter | 健康探测涉及 `fetch` 与超时，按 adapter 处理（见下） |

**adapter 模块职责**

| 模块 | 职责 |
|------|------|
| `adapter/index.js` | 插件入口：`name` / `inject` / `Config` / `apply(ctx, config)`；装配各接线；全部 effect 清理 |
| `adapter/settings.js` | `Config` schema 声明、volatile 字段现读、schema 校验挂点 |
| `adapter/profile-writer.js` | **全包唯一持久写出口**：把 `core/profile.js` 产出的 payload 原子写入 `profiles/<hash>.json`（临时文件 + rename） |
| `adapter/process.js` | `ctx.subprocess` 接线：解析可执行、spawn、状态维护、终止与等待；持有进程句柄 |
| `adapter/health.js` | `/healthz` 探测（回环 + Bearer token + 超时），供状态面对外呈现 |
| `adapter/rpc-channel.js` | `/api/codexpro/<endpoint>` 精确 Fetch 路由注册与信封解析 |

## 三、可执行解析约定

这是本插件唯一一处平台敏感的定位逻辑，须严格遵循下述已验证事实：

- **不得**以裸名 `codexpro` 交给 `ctx.subprocess.spawn`。Windows 上该名字解析到 `.cmd` shim，在 `argv` 不经 shell 解释的语义下直接 `ENOENT`（已实测）。
- **正确形态**：以 `process.execPath`（Node 可执行）为 `argv[0]`，`argv[1]` 为 codexpro 的 CLI 入口 `scripts/codexpro.mjs` 绝对路径（已实测可启动并输出版本）。
- CLI 入口路径由 `adapter/process.js` 通过包解析得到（`createRequire` 解析 `codexpro/package.json` 后取其 `bin` 指向），**不硬编码绝对路径**；解析失败时以稳定错误码呈现，不回落到裸名。
- 这一层是 C-08「平台相关行为必须隔离」的落点：平台差异只允许出现在本约定与 `技术栈设计.md` §五的表格内。

## 四、配置与状态的所有权

| 数据 | 所有者 | 存放位置 | 生命周期 |
|------|--------|----------|----------|
| 用户意图（授权集、tunnel、端口、bash/写入模式） | DSH profile 条目 `Config` | 该 profile 的 `cordis.patch.yml` 中本行 `config` | 随 profile 持久 |
| codexpro profile 文件（`allowedRoots` 等投影） | codexpro | `<$DSH_HOME>/codexpro/profiles/<hash>.json` | 由插件单向写；可随时由意图重建 |
| 进程运行态（pid、状态、当前 URL） | 插件内存 + codexpro 自身 runtime 文件 | 内存为主，`codexpro/runtime/<hash>.json` 为 codexpro 所写 | 进程结束即失效 |
| HTTP token | DSH profile 条目 `Config`（`.volatile()`） | 同「用户意图」 | 跨启停稳定（C-07） |

**不变量**：

1. 插件不保存任何 codexpro 之外的会话状态；卸载即无残留。
2. codexpro profile 文件是**投影**：删除它不丢用户意图，下次同步可完整重建。
3. token 一经生成不再更改，除非用户显式重置。
4. `allowedRoots` 中每一项都必须存在于 DSH 工作区注册表，且目录当前存在（C-09）。

## 五、全局约定

- 文件名统一小写连字符；模块内导出小写驼峰函数名。
- 路径归一统一用 `fs.realpathSync.native`；不使用 `path.resolve` 代替 realpath。
- 持久写只允许经 `adapter/profile-writer.js`；其他模块不得直接 `writeFile`。
- 进程句柄只允许由 `adapter/process.js` 持有；其他模块不得直接 spawn。
- 平台相关分支只允许出现在 `adapter/process.js` 的可执行解析处，且必须附注释说明依据。
- Host 半区无构建（`.js` 即交付），Client 半区产物 `dist/client.js` 入库并由 `--check` 哨兵守护新鲜度。
- 插件包内不得保存用户数据、缓存或会话状态。

## 六、RPC 通道

沿用本仓库既有约定（`docs/decisions/0002`）：使用 `ctx.connection.fetch.register` 注册 `/api/codexpro/<endpoint>` 精确路由，**不使用** `connection.rpc.handle`（该 API 在生产 web 组合下无法注册任何自定义 channel）。命名空间固定为 `codexpro`。端点清单归 `technical-details/RPC通道与设置页.md`。
